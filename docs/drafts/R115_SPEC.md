# R115 规格：地标、建筑化与新怪物

2026-10-23 Claude 起草，用户已定范围：**新怪物 + 单方块物件建筑化 + 三大地标**。NPC、库罗本体、首领专属场地与首领放大暂缓。
分工：**Codex 实现**（含生成器、模型、运行时与测试），**Claude 写规格并验收**；Codex 做不好的部分由 Claude 接手。
沿用规则：不复制 Moon Studios 原件，私人使用可沿用 Ori 命名；客户端只用 llvmpipe + `DISPLAY=:0`；已有存档/注册 ID 不破坏。

## 交付顺序与检查点

每个阶段结束发检查点（JUnit/GameTest 数量 + 实拍目录），Claude 验收通过后再进下一阶段。

| 阶段 | 内容 | 验收重点 |
|---|---|---|
| A | 先祖之树更名 + 五类单方块物件建筑化 | 外观达到「一眼看出是什么」，交互不变，旧存档不坏 |
| B | 大灵树（全世界唯一） + 复苏结局迁移 | 远处可见的地标、内部可走、`/locate` 可找 |
| C | 金索树 + 涨水逃亡 | 内部竖向攀登路线可通关，逃亡可失败可重试 |
| D | 三种新普通怪 | 原创外形、预警可读、可用现有能力应对 |

## A. 先祖之树 + 单方块建筑化

**A1 先祖之树**：现有小灵树（`orimod:spirit_tree` 结构/特征，功能是每人每棵学一项技能）在显示层改名为「先祖之树 / Ancestral Tree」，注册 ID、存档 rewards 键、命令名全部不变。萤提示、面板、指引文本同步。「灵树」一词留给 B 的大灵树。

**A2 建筑化**（交互方块保留为核心，外观升级；以下尺寸是目标，不是硬约束）：

| 物件 | 现状 | 目标 |
|---|---|---|
| 灵泉 `glades_well` / 遗迹神龛 `*_shrine` | 单方块，借用森林泉贴图 | 约 3×3 底座的发光水池神龛：石盆+浅发光水面+两根弯拱根须或石拱；核心方块在中心。三种遗迹神龛按遗迹主题换材质（林泉苔石、溪谷蓝石、洞穴深板岩），同一套形体 |
| 首领祭坛 `storm_altar` / `gloom_altar` | 单方块 | 2–3 格高的祭坛：台阶底座+悬浮/嵌入的主题核心（风暴=旋转羽环，腐光=紫色裂晶），未激活/激活/首领已败三态外观 |
| 地图石 `map_stone` | 单方块 | 2–3 格高的刻纹石柱，顶部浮空的地图碎片/光盘，激活后纹路发光 |
| 钥石门 `keystone_door` | 方块拼墙 | 圆形大门（门框环+中心门扇），插槽可见钥石数量，开门有动画/坍缩效果；占用原门洞格子 |

实现方式由 Codex 选：多方块模板（新放置处）或方块实体渲染大模型（旧存档自动生效）。要求：
- 旧存档里已生成的方块必须仍可交互、不报错；能自动升级外观的优先（方块实体渲染）。
- 遗迹模板若要改尺寸，路线/光桥/秘室契约测试必须原样通过；不能堵路。
- 碰撞箱不阻挡原有路线；大模型只做视觉的部分不得让玩家卡进去。
- 模型可用 Blender 脚本程序化生成（参考 `scripts/art/build_monster.py`、`build_first_person.py` 的源→打包→manifest 流程），源文件进 `art/source/<name>/`。

## B. 大灵树（The Spirit Tree）

全世界（主世界）唯一的巨型地标，对应 BF 开场的灵树。
- **位置**：出生点附近 300–800 格内恰好一棵（建议结构 `orimod:great_spirit_tree` + `concentric_rings` count 1，或等效的唯一放置）；偏好森林/平原类群系，避开海洋、山峰。`/locate structure orimod:great_spirit_tree` 必须成功。放大后的选址只要求44格根区承重干地/起伏合格，44–80格悬冠可越湖岸，深水采样不得超过60%；完整足迹与缓冲仍不得覆盖已开发区块。新档保持300–800上限，旧档只在原环已开发时允许向2500拓展。
- **体量（C课程993a88f后用户调整）**：高约200格，冠顶世界y约280–300；主干基部28–32格，冠下22–24格（放大实拍后修正）；冠幅140–160格，最低层最宽且近平展、窄中层和小顶层间留6–10格天空缝，主枝根部10–12格粗、两级弯叉后渐细到4格，板根伸30–40格。先交250格以上日夜/树基/冠下光照检查点，再接内部。旧世界保留旧树，不重建；金索树后续放大按 C 的最新分关要求。
- **冠下安全/性能**：真实发光根结/悬藤补照，敌对自然刷怪保护兜底；实测冠下方块光，不能用emissive贴图代替。记录最重逐块写入（单次约100ms可接受）及llvmpipe140格机位FPS。
- **内部**：低层保留无技能可达的树心大厅和根洞；外形通过后新增从大厅贯穿主干至云上瞭望台的灵风竖井，并配无技能梯/阶梯替代或明确安全下行，不得软锁。
- **玩法**：
  - 复苏结局（R108 三光仪式）只在大灵树之心触发；先祖之树不再触发结局，但赐福功能不变。
  - 大灵树本身不发技能；可设一个一次性灵光/能量格奖励。
  - 萤首次看到大灵树的提示与台词；地图石/路路的指引可指向它。
- **技术**：多区块结构，按区块切片写入（结构 piece 跨区块、每个区块只写自己范围），不能出现区块边界断层；与遗迹/驿站/先祖之树互斥；地形融合用 beard 或自带地基，不留垂直切面。性能：生成单区块写入时间要测。

## C. 金索树（Ginso Tree）

稀有的巨型空心古树，对应 BF 的金索树与涨水逃亡。
- **位置/密度**：稀有结构（建议约 1–2 千格一棵），偏好沼泽/河流/湿润森林；`/locate` 可找。
- **体量（42a50ec 后用户调整）**：新金索树高约100–120格，基干18–22格，根伸18–25格，全宽≤70；保持扭转空心柏塔、三断叉、单侧垂苔冠，明显小于大灵树。外形关卡A先验收，之后才开内部关卡B；逃亡仍暂停。
- **内部路线**：自下而上的竖向关卡，必须综合使用现有能力：蹬墙/攀爬、猛击灵灯、抓钩花、上升气流、二段跳；新版关卡B中途3个灵泉检查点，五段按新高度重排，任何课程落脚面失误应在≤10格内由承接面或免伤缓冲接住；缺技能至少能安全退回入口。顶层「水之心」祭坛靠近冠部，为日后向上/向外逃亡留空间。
- **版本/旧档**：动代码前从42a50ec冻结旧体素/哈希；旧树ShapeVersion2/CourseVersion1逐格保留，新树最终必须ShapeVersion3/CourseVersion2。A暂配v3/v1只作外形检查点，不独立提交。
- **放大密度补偿**：先让根足向当地地面延伸，严格起伏只限树干基部圈；64/24仍不足旧密度80%时已批准52/20，最终两固定种子的实际locate密度必须各在旧值±20%。完整新足迹碰到已有磁盘区块/已完成结构引用的区块时以GENERATED拒绝，不加载区块检查。
- **改网格的定位限制（已确认接受）**：旧网格上生成的树保留，但原版locate按新网格搜索，可能不再返回旧树。不扩展双网格locate（现有游戏内指引不依赖金索定位）。升级回归须直接读旧起点并检查完整方块，同时证明新版locate跳过已探索区无树的候选点，返回实际完整的新树。
- **逃亡**：取得水之心后触发涨水（清水或腐光水，Codex 选，需与流体规则一致），水位按固定速度上涨，玩家需沿新开的路线向上/向外逃到树冠出口；失败（被淹没/死亡）则重置水位，可重试；成功给奖励（生命格或能量格 + 灵光），每人一次。复用/扩展 `EscapeSequence` 的计时、伤害与奖励框架。
- **安全**：逃亡期间不能把玩家困死在不可达位置；涨水只在树内体积内，结束后排空/还原。

## D. 新普通怪（3 种，原创外形）

参考 BF 的小型怪类型，但造型、名字原创（腐光系，紫色发光件 + 暗紫躯体，沿用五怪的配色与动画契约）：

| 名称（暂定） | 原型参考 | 行为 | 应对 |
|---|---|---|---|
| 腐光团 Gloom Blob | BF 史莱姆/分裂怪 | 成群地面怪，弹跳接近，被击杀分裂成 2–3 个小团（小团不再分裂） | 范围攻击（光爆/蓄力灵焰/锤）有优势 |
| 攀壁虫 Gloom Crawler | BF 爬墙怪/蜘蛛 | 沿墙/天花板爬行，玩家进入下方时预警后扑落 | 下砸、猛击反弹；落地后短暂硬直 |
| 跳跳蟾 Gloom Leaper | BF 青蛙/跳跃怪 | 蓄力后抛物线大跳，落地冲击波；空中可被猛击借力 | 空中猛击、跳过冲击波 |

- 刷新：腐化地带周边、遗迹内、潮夜波次加入；不做全图自然刷新。创造/旁观玩家不被攻击（复用 `GloomTargets`）。
- 每种：预警片段、受击/死亡动画、掉落灵光；甲虫式的 glTF 视觉管线（`GloomCreatureVisual`）。
- 测试：AI 行为 GameTest（分裂数量、扑落预警时长、跳跃落点冲击范围）、与潮夜/腐化地带集成回归。

## 验收方式（Claude）

- 每阶段：Codex 提交实拍目录（白天/夜晚远景、近景、内部路线、交互前后），Claude 看图判定；路线类给出真实输入通关记录。
- 新结构：新存档 `/locate` + 现场截图；遗迹旧测试全部原样通过。
- 美术质量不达标时由 Claude 给修改意见；两轮仍不达标，Claude 接手该资产。
