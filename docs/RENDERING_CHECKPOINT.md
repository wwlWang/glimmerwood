# 渲染联调记录

主体技术样例记录日期为 2026-10-15；后附 R10–R12 正式角色渲染回归。以下局部结果不代表完整首版已验收，逐项状态见 [ACCEPTANCE_STATUS.md](ACCEPTANCE_STATUS.md)。

## 结果与证据

环境沿用 `evidence/development-tools-2026-10-14` 的本机记录；实际加载列表与设置保存在 `evidence/rendering-2026-10-15/state.json`。使用 MC 1.21.1、NeoForge 21.1.248、Java 21、RTX 4070 Laptop，1920×1080、12 区块视距、关闭垂直同步，帧率设置值 260。

- GemRender 蒙皮角色、Mellow 动态阴影与 Photon 透明微粒同时显示。组合截图：`evidence/rendering-2026-10-15/reload-5.png`。
- 五次完整资源重载成功，每次只存在一个预览实例；循环粒子自动重建。状态与每次截图见同一证据目录。
- 窗口依次切换为 1280×720 和 1920×1080，实际帧缓冲尺寸匹配；最终性能测量使用恢复后的 1080p。
- 60 秒独立性能采样取得 7595 个帧间隔：平均 126.62 FPS，帧时间中位数 7.44 ms，P95 10.86 ms，P99 16.32 ms；最大 120.85 ms，16 帧超过 50 ms。它只是单角色静态场景基线，不能证明跑酷、复杂场景或长时间运行的性能。
- `animation-stream.mp4` 是 20 秒、1920×1080、30 FPS 输出，共 600 帧；实际采集 562 帧，38 个时隙保持前一帧。清单在 `run-devtools/devtools/animation-stream-2026-10-15/frames.json`。已抽帧检查角色、阴影与微粒；正式动作衔接尚未验收。
- 初版 `animation.mp4` 因 PNG 写入瓶颈只采到 60 帧，不能用于流畅度判断，保留作为失败记录。
- 从未修改的下载原件重新生成 v008 源文件及导出物，GLB 和贴图哈希与 v007 一致；见 `asset-reproducibility.json`。

## 已定位的问题

1. 无贴图 glTF 材质落到 Flywheel 默认方块图集，导致杂色。导出增加独立 PNG 与图片的 `extras.resourceLocation`，开关光影均复测正常。
2. Mellow 默认关闭动态阴影。兼容预设显式打开动态阴影、2048 阴影图和 0.5 实体阴影距离比例。
3. Colorwheel 下默认圆形阴影成为过黑圆盘。光影开启时不添加该组件，改用实际蒙皮几何投影；关闭光影时技术预览保留原版阴影。
4. 光影重建后 Photon 缓存旧渲染目标。开发接口调用 `IrisCompat.invalidate()` 后，开关光影均能保留可见微粒，截图为 `run-devtools/devtools/shader-off-binding-refresh.png` 和 `shader-on-binding-refresh.png`。正式设置入口仍待集成。
5. 资源重载清除循环效果。样例持有运行实例并检查有效性，失效后在同一锚点恢复，离开世界或锚点改变时停止。

## 2026-10-18：玩家渲染层 R10

角色模型改用正式 v010 后，现保留原版玩家渲染入口、事件、名牌与缓冲区。GemRender 只提供身体和骨骼姿态；原版附件层在同一实体渲染阶段使用该姿态。原先实体结束后逐手提交持物的路径已移除，背包也共用附件适配。

`audit-r10-layers-v004-2026-10-18` 的 24 张对照覆盖身体、全套钻石甲、持物、南瓜头、鞘翅、披风、鹦鹉、箭与蜂刺、队伍色轮廓、隐藏名牌、隐身装备、隐身轮廓、人形恢复和墙后轮廓，各含 Mellow 开/关。全部截图已查看。发光边界来自实际蒙皮几何，箭与蜂刺在实际网格顶点上选锚点。测试实体仅存在客户端，不写入存档，也不是联机结果。

`audit-r10-motion-v002-2026-10-18` 保留 14 秒、1080p、30 FPS 原速录像，输出 420 帧，实际采集 416 帧；已按每 0.1 秒一帧检查完整时间段，装备跟随走、跳、蹲、拉弓与释放。最新代码的 v003 同路线完成，419 帧实际采集、420 帧输出；14 张补充截图确认左右手、第一人称、生存背包中的甲/鞘翅/头部物品和两次资源重载。v001 错用创造物品栏，背包部分明确无效。

实体火焰在移除地面火方块、走离原位置后仍显示，光影开关均已查看。先在人形展开鞘翅再变身，能够保持 `FALL_FLYING`，双翼会展开。直接用 Ori 起飞则失败，根因是跳跃接管，留待兼容修复。激流尝试未进入旋转状态，其旋转层未验收。原版护腿在屈膝时存在可见穿插，复杂姿态外观也未验收；不能用层已恢复替代 ART03、ART06、ART07 全项通过。

早期头盔过大、肩部鹦鹉过高、头部物品露出鼻尖，以及首次 Mixin 描述符错误均保留失败记录。最新启动和退出成功，日志没有本轮渲染异常；外部依赖对未安装兼容模组的类查找警告仍存在。

## 2026-10-18：激流与鞘翅 R11

鞘翅起飞冲突已通过真实按键修复并复测。水中使用激流三叉戟后，两端均进入 `SPIN_ATTACK`；角色改用水平姿态并围绕躯干旋转，持物和原版旋转效果共用该变换，结束后回到下落与落地动作。

最终证据为 `audit-r11-flight-v004-2026-10-18`。两种光影状态各保留三秒、1080p、30 FPS 原速视频，均输出 90 帧，实际采集分别为 86 / 81 帧；已抽帧查看开始、旋转和退出，完整落地在同轮逐 tick 状态中确认。该记录证明状态与表现接通，帧采集丢帧不作为性能达标依据。

## R20：自带光影 Spirit Glow（ENV05）

- 上游：Codeberg `TheCMK/mellow-shader` 提交 `3ad9445`（2026-09-19）。其 `shaders.properties`、`block.properties`、`item.properties` 与英文语言文件和 v3.4.1a 发行包逐字节相同，而 v3.4.1a 已在本机 Iris 1.8.12 / MC 1.21.1 验证（`rendering-2026-10-15`），故直接采用，无需移植或换旧版本。
- 导入 `shaders/`、`LICENSE`、`LICENSE-APACHE`；未导入仓库截图和 `mellow.png` 调色表。改名、致谢、自制调色表见包内 `CHANGES.md`。
- 运行：模组首次客户端 tick 将包写入 `Iris.getShaderpacksDirectory()/Spirit Glow.zip`（只替换自己的文件，内容相同则不写）；切换经 `IrisConfig` 保存后 `Iris.reload()`，再调用 Photon `IrisCompat.invalidate()`。Iris 为 `compileOnly`，只有 `SpiritGlowIris` 引用它，且仅在装有 Iris 时加载。
- 云端：llvmpipe 能编译运行 Mellow 与 Spirit Glow 管线（日志只有原包已有的兼容性补丁警告与缺失标签警告）。帧率 2–20 FPS，不代表性能。截图存于云端 `/workspace/oriMod/shots/r20-*`，只作管线可运行的证据。
- 待本机：真实 GPU 上的观感、帧率、与 Photon 微粒/角色发光共存的复查，以及发行 JAR 在干净实例上的首次安装。
