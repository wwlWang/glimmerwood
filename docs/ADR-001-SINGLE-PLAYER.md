# ADR 001：首版按单人集成服务器交付

日期：2026-10-18。状态：采用，延续已确认的 `PROJECT_PLAN.md`。

## 范围

首版交付单人存档中的获取、移动、战斗、成长、探索和保存流程。用户已明确仅供自己玩。多人联机、远端玩家动作呈现及专用服务器玩法支持属于后续版本。

无界面 GameTest 和专用服务器能够启动，只证明公共逻辑没有加载客户端渲染类，并提供服务端规则测试环境。它们不代表多人玩法已通过验收。

## 当前职责

客户端采集按键，立即预测普通跳跃、二段跳和墙跳，并通过原版碰撞移动。服务端接收有序输入，校验能力、次数、目标、冷却和战斗阶段，决定动作是否成立。两端共用 `MovementRules`；服务端伤害、奖励与存档保持权威。

移动结果目前只发送给操作角色的客户端。其他玩家缺少对应的动作状态、起始时间和插值数据，因此不能承诺远端动画正确。客户端执行速度不是多人反作弊方案。

输入失活和动作续期有明确时限。滑翔允许短暂续期容错，本地松键、下蹲、碰墙、入水及界面切换仍立即退出。集成服务器停顿测试用于检查单人卡顿恢复，不能代替真实网络的延迟、丢包和乱序测试。

实际传送由服务端发送位置同步的入口通知移动系统，清理动作与排队输入，再同步空中次数。连续位移不再按每 tick 超过八格推断为传送。

## 后续联机需要补齐

- 将动作起点、阶段和结束状态同步给追踪该玩家的客户端，处理加入视野、离开视野和重新连接。
- 定义服务端移动约束、预测确认和位置纠正协议，分别测试真实延迟、抖动、丢包与恶意输入。
- 明确冻结目标、挑战实例和奖励在多个玩家同时参与时的所有权与冲突规则。
- 在独立服务端和至少两个真实客户端之间执行完整玩法验收。

这些工作不计入首版单人完成条件。新增共享规则与固定协议编号为后续复用提供基础；协议版本升级仍须同步更新两端。
