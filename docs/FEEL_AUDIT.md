# 手感审计（FEEL_AUDIT）

2026-10-19 R72。起因是本机试玩反馈：“感觉好僵，动作/效果完全没那感觉，没有丝滑的感觉；贴图也欠缺”。从本轮起暂停加新功能，先做手感和流畅度，再做贴图。

数字来自两处：

- 读代码：`movement/SpiritMovement`、`MovementRules`、`AirMovement`，`client/SpiritControls`、`SpiritJumpPrediction`，`network/MovementResultPayload`，`client/render/SpiritAnimation`、`SpiritPlayerVisual`。
- `scripts/feel_curves.py` 的模拟：按 1.21.1 原版玩家物理计算（地面摩擦 0.6×0.91=0.546，空中 0.91，重力 0.08 后乘 0.98 阻力），新规则的常量直接从 `FeelTuning.java` 解析。输出 `feel-curves.png` 和 `feel-metrics.json`，放在云端 `/workspace/oriMod/shots/`。

单位：1 tick = 50 ms（20 TPS）；速度写作 格/tick（b/t）或 m/s。

## 1. 发现的问题（R72 之前的实际数值）

### 1.1 地面与空中水平运动：完全是原版

精灵形态没有接管水平移动，用的就是原版 `travel`。

| 项目 | R72 前 | Ori 参考 | 问题 |
| --- | --- | --- | --- |
| 最高速度 | 走 4.41 m/s，疾跑 5.73 m/s，而且疾跑要双击或按住疾跑键 | 一按方向就是全速奔跑 | 慢；走和跑分两档 |
| 加速到 90% | 4 tick（200 ms），是按指数逼近 | 约 2–3 帧到 0.1 秒内 | 略慢，起步发“粘” |
| 松手到停（剩 10%） | 4 tick，滑行 0.34 格 | 几乎立刻停 | 停不住、发滑 |
| 空中操控 | 每 tick 加速 0.02，空气阻力 0.91，从静止加到 0.2 b/t 需要二十多 tick | 空中转向强 | **几乎不能在空中改方向**，这是“僵”的主要来源 |
| 转身 | 原版身体朝向缓慢追随视角（`yBodyRot`），每帧限速 | 瞬间转向并带惯性 | 模型转身慢半拍 |

### 1.2 跳跃弧线：原版固定抛物线

| 项目 | R72 前 | Ori 参考 |
| --- | --- | --- |
| 跳跃高度 | 按住与轻点都是 **1.25 格**（不支持可变跳高） | 按住越久跳越高 |
| 起跳到顶点 | 6 tick；滞空共 12 tick（0.6 秒） | 上升轻，在顶点悬停一下 |
| 顶点悬停（离顶点不到 0.1 格的 tick 数） | 4 | 明显更长 |
| 下落重力 | 与上升相同（0.08），最大下落速度约 −3.9 b/t | 下落比上升重，并有上限 |
| 土狼时间 / 跳跃缓冲 | 2 tick / 2 tick（`MovementRules`，各 100 ms），由服务端判定 | 约 100–150 ms，差不多 |

跳跃本身已经在客户端预测（`SpiritJumpPrediction`），输入当帧就生效，**没有延迟**。

### 1.3 冲刺（Dash）

- 速度曲线是矩形：5 tick 恒速 1.12 b/t（22.4 m/s），结束那一 tick 落地摩擦直接乘 0.546，速度一下掉到 0.74 b/t，剩余动量很快被吃掉。没有缓出，也没有把动量带进奔跑。
- **冲刺有输入延迟**：客户端按键后不先行移动，要等服务端 `signal(DASH)` 回到客户端，`state.activeTicks` 才被置位。单机下是 1–2 tick（50–100 ms），联机还要再加一个往返延迟。滑翔、Bash 瞄准、牵引、下砸、蹬墙滑也一样由服务端确认后才开始。
- Launch 和 Bash 释放的速度同样要服务端回包才生效，单机延迟 1–2 tick。

### 1.4 服务端校正与卡顿

- 位置以客户端为准（MC 原版机制），服务端只校验动作，所以正常移动不会被拉回。会造成拉回的只有两种情况：一是拒绝预测跳跃时（`rejectJump` 里的 `teleport`），二是 `hurtMarked` 速度包；后者只在 Launch 和击退时出现。
- 渲染位置已经按 `partialTick` 逐帧插值（`getPosition(partial)`），动画时钟也是逐帧的，**不存在逐 tick 跳动**。云端只有约 10 FPS，体感上的卡顿主要来自上面这些运动曲线，而不是插值。

### 1.5 动画

`ori.glb` 有 58 个剪辑：起步、停步、左右转、起跳、上升、顶点、下落、轻落地、重落地、冲刺开始和结束、二段跳、左右蹬墙跳、滑翔开合等都有，**剪辑本身不缺**。问题出在混合方式上：

| 项目 | R72 前 |
| --- | --- |
| 基础剪辑交叉淡入淡出 | 0.11 秒（2.2 tick），二段跳 0.045 秒，太硬 |
| 走 / 跑 | 在 1.8 和 2.3 m/s 两个阈值之间硬切换（带回差），不是按速度混合 |
| 上升 / 顶点 / 下落 | 按 dy 是否超过 ±0.07 硬切换 |
| 身体倾斜 | 没有：加速、刹车、转弯时身体不前倾也不侧倾 |
| 挤压与拉伸 | 没有 |
| 耳朵和尾巴的次级运动 | 只有一个一阶滞后（按偏航角速度，指数系数 9），不会过冲回弹，也不随纵向速度飘动 |
| 呼吸 | 只有剪辑自带的，没有叠加层 |

### 1.6 镜头与特效

- 镜头是原版：第三人称硬跟随，没有滞后，也没有前瞻；FOV 只随移动速度属性变化，冲刺时没有 FOV 冲击。
- 特效只在动作发生时一次性播放（冲刺、跳跃、Bash 等），滑翔有持续粒子。**移动时身上没有持续的柔光拖尾，没有脚步光点，冲刺也没有残影**。原作 Ori 身上始终带着一条发光拖尾。

### 1.7 贴图

物品和方块几乎都借用原版贴图：灵格用原版图标，钥石是回响碎片，地图碎片是纸，灵沙是可疑的沙子，祭坛和石台是深板岩、黑石之类，武器借用三叉戟、锤子等。整体风格不统一，也没有 Ori 那种柔和的手绘色调。
