# OriMod 项目计划大纲

版本：0.1，已确认

日期：2026 年 10 月 14 日

用途：作为首版实现、资产制作和验收的共同依据。用户于 2026 年 10 月 14 日确认计划，并授权初始化 Git、MDK 和检查模型资产；当前进入 P1 工程准备。

## 1 项目目标

在 Minecraft 的方块世界中，玩家获得精灵核心，变身为接近 Ori 原作比例的圆润角色，使用连续跑酷和灵光战斗能力探索原版世界。模组提供默认启用的风格化画面方案，让森林、洞穴、水面和角色发光呈现鲜艳、柔和、有绘画感的观感。

首版是一套可持续游玩的单人玩法，包含获取、成长、探索、战斗、死亡恢复和存档。模型源文件、动画源文件、特效工程、构建方式与验收证据随项目交付。

核心体验样例：玩家在林间发现灵迹，变身后沿树干蹬墙，冲刺越过缺口，借投射物猛击弹射，再展开滑翔抵达祭坛。动作、耳尾惯性、拖尾、声音和镜头连续衔接；落地后可直接打开箱子或继续采集。

## 4 获取与成长流程

### 4.1 进入玩法

1. 首版提供精灵核心配方，暂定四个铜锭、四个玻璃和一个铁锭，允许普通早期生存获取。配方为平衡初值。
2. 首次使用核心后永久记录已觉醒。核心随后作为入口道具，不要求一直占用快捷栏。
3. 玩家获得墙面动作、二段跳和灵光刃；引导解释变身、镜头、普通采集、能量与能力解锁。
4. 能力面板列出当前可解锁能力、前置要求和操作演示；引导可重新查看。
5. 首次觉醒发放可重新制作的灵迹指引物，指向尚未完成的可达灵迹。定位有距离上限和失败提示。

旧存档通过相同配方进入。结构仅在新生成区块出现；指引找不到结构时明确说明继续探索新区域，能力解锁仍有普通生存获取灵光的路径。

### 4.2 解锁顺序

| 阶段 | 内容 | 初始解锁成本 |
| --- | --- | --- |
| 觉醒 | 墙面动作、二段跳、灵光刃 | 免费 |
| 灵动 | 地面和空中冲刺 | 20 灵光 |
| 借力 | Bash 猛击 | 30 灵光 |
| 御风 | 滑翔 | 30 灵光 |
| 牵引 | 对牵引花或专用锚点移动 | 40 灵光 |
| 坠击 | 空中下砸 | 40 灵光 |
| 战斗支线 | 灵光弓，冲刺解锁后可购买 | 30 灵光 |

成本属于可调参数。普通敌对生物暂定提供 2 灵光，灵迹首次发现提供 15，挑战首次完成提供 30，重复挑战提供少量奖励。每个发现与首通奖励有唯一记录，避免重复读档和重新加载区块刷取。

能力解锁不消耗原版经验。灵光、已解锁能力和碎片在死亡后保留。挑战入口展示所需能力；尚未满足时不能被送入无法完成的挑战。

灵光武器以物品形式使用，首次解锁可领取一件；背包已满时保留待领取状态。丢失后可按解锁配方重新制作，物品掉落遵循原版死亡规则，永久解锁记录保留。使用武器需要对应能力，重复使用核心不能反复领取首次赠送物品。

### 4.3 战斗能量与碎片

战斗能量用于灵光弓和后续主动战斗效果，停止消耗后逐步恢复。零能量仍可跳跃、冲刺、Bash、牵引、滑翔和使用灵光刃，防止移动中断造成困死。

首版五种碎片：能量容量、能量恢复、灵光拾取范围、受击恢复、空中操控。最多装备三个不同碎片，槽位随成长解锁。碎片不能叠加到无限飞行、永久免伤或跳过基本碰撞；能力面板直接显示效果与取舍。

初始开放一个碎片槽，解锁 Bash 后开放第二个，解锁牵引后开放第三个。普通难度与和平难度均保留发现、挑战等非击杀灵光来源。

## 5 玩家形态与原版交互

### 5.1 变身规则

默认按 V 切换；第一次变身切换到第三人称，之后记忆玩家选择，退出精灵形态恢复先前视角。变身过程保留玩家实体、物品栏、生命和原版身份数据。

精灵模型初始设计身高约 1.2 格、碰撞宽度 0.6 格，最终以灰模中的落地、视线和通道测试确定。恢复人形前检查人形碰撞空间；空间不足时保留精灵形态并提示，避免挤入墙体。变身不清除坠落速度、着火、中毒或受伤状态。

### 5.2 生存动作

盔甲属性保留，精灵外观默认隐藏原版盔甲模型。工具、火把、食物、盾牌和弓有正确持物位置。挖掘、放置、开箱、交易、拾取、睡眠、游泳、攀梯、乘船、矿车、传送门和死亡画面必须可用。

动作系统具有明确优先级：死亡或传送清理、乘坐与睡眠、受击中断、技能动作、普通移动、待机和次级动画。进入原版特殊状态时终止不适用的技能，退出后恢复，不沿用上一次空中动作。

第三人称准星与交互射线统一，不能出现准星指向箱子却挖到旁边方块的持续偏移。第一人称显示精灵手部，保持工具使用和技能目标提示；不会为每一种第三方物品额外制作动作。

## 6 操作与移动设计

### 6.1 默认键位

| 输入 | 精灵形态行为 |
| --- | --- |
| WASD 和鼠标 | 移动与观察 |
| 空格 | 跳跃、二段跳；下落时按住展开已解锁的滑翔 |
| C | 冲刺；空中按潜行键加 C 使用已解锁的下砸 |
| R | 对普通可借力目标进行 Bash；对专用牵引锚点进行牵引 |
| V | 切换形态 |
| G | 能力、碎片与操作说明面板 |
| 潜行键 | 释放墙面附着、停止滑翔，保留潜行交互 |
| 攻击和使用键 | 遵循当前手持物品；灵光武器使用各自攻击方式 |

保留 E 物品栏、F 副手交换和原版冲刺设置。所有新增键可重绑定，中文提示跟随实际绑定；文本框、菜单和游戏失焦时不触发技能。

### 6.2 移动规则

| 能力 | 行为与边界 |
| --- | --- |
| 墙面动作 | 向可接触墙面输入时附着或滑墙，按跳跃蹬出；主动释放有效；墙角不会反复吸附抖动 |
| 二段跳 | 每次离地有一次额外跳跃；接受短输入缓冲和离地宽限；进入菜单不积存下一次跳跃 |
| 冲刺 | 地面短冲刺，空中初始一次；方向以输入和视角约定计算；沿路径检测碰撞，不能穿过薄墙 |
| Bash | 借可见的指定敌人、投射物或灵光锚点向选定方向弹射；对可推动目标施加反向反馈 |
| 滑翔 | 持续减缓下落，允许转向；贴墙、入水、落地或主动释放时正确收起 |
| 牵引 | 只作用于明确标识的牵引花或专用锚点；路径受阻、目标失效时可取消并正常下落 |
| 下砸 | 有空中高度要求，向下加速；命中地面触发范围反馈与伤害；默认不破坏方块 |

首轮手感参数采用输入缓冲 100 毫秒、离地宽限 100 毫秒，动作中断在下一次允许的游戏更新生效。数值在测试路线中调整并记录；视觉动画按渲染帧采样，不把提高动画采样率等同于提高游戏逻辑更新率。

空中次数由落地、成功蹬墙或有效 Bash 等显式事件恢复。同一目标的短期重复利用和同一接触面的连续复位受限制。任何能力结束后，重力、碰撞、坠落伤害与玩家控制都回到确定状态。

### 6.3 三维 Bash

候选目标经过距离、视线遮挡和类型检查，优先准星附近目标。初始搜索范围 6 格；范围和目标优先级可调。高亮明确区分 Bash 目标与牵引锚点，隐藏或失效目标立即退出候选。

按住 R 进入最长 0.6 秒的瞄准窗口，用方向箭头表达发射方向，松开执行。单人首版暂定对玩家与被选中的可移动目标短时挂起位移，其他世界逻辑照常运行；退出时恢复被接管状态，目标被移除或区块卸载也必须清理。该手感在早期小样中验证，若目标定位和可读性不成立，调整瞄准方案后再冻结。

瞄准挂起不等于免伤；受击可取消。不能对不可交互实体、穿墙目标或已死亡目标成功施放。UI、音效和实际弹射采用同一个已验证目标。

## 7 战斗设计

灵光刃采用三段连击。每段有准备、命中和恢复区间，输入可在规定窗口衔接；移动技能能按明确规则取消恢复段。攻击范围、目标去重和伤害由游戏逻辑决定，视觉拖尾只负责表现。

灵光弓支持按住蓄力、释放射击和取消，消耗战斗能量。准星、发射方向、命中反馈一致。初始版本不加入自动追踪或多种箭矢。

受击采用短促反馈和方向反应。镜头震动、闪光和停顿强度可降低或关闭。恢复人形、切换物品、打开菜单和死亡时，武器动画、蓄力音效与持续特效一起停止。攻击判定不因帧率改变而重复触发。

## 8 探索点和挑战

| 类型 | 场景内容 | 挑战重点 |
| --- | --- | --- |
| 林间灵泉 | 原版方块搭建的小型树根与泉池空间，带发光植被 | 墙面移动、二段跳和冲刺路线 |
| 溪谷灵迹 | 台阶、水池与灵光锚点，可看见明确终点 | Bash 借力和滑翔衔接 |
| 洞穴祭坛 | 保持可读性的洞穴区域，配置牵引锚点和练习目标 | 牵引、下砸与灵光武器组合 |

结构由模板和受控生成规则组成，保留原版方块形态。生成避让危险地形和不合适高度，挑战起终点有安全站立位置。首版各交付一个正式模板，并用多个自然生成世界验证可发现性。

挑战先读要求再开始，能够中途退出。失败后返回本挑战安全点并恢复挑战专用临时对象；普通世界死亡仍遵循原版规则。挑战计时、首通奖励和重复奖励持久化。每个模板都提供无需命令的正常入口，以及仅开发环境可用的直接测试入口。

挑战复位只处理自己创建的临时对象，不覆盖玩家后来建造的方块。启动前检查关键锚点与安全落点；结构被改造到无法完成时，说明缺失条件并拒绝启动。极限模式保留原版死亡规则，挑战失败返回安全点不能覆盖已经发生的玩家死亡。

## 9 模型和动画资产

### 9.1 制作工具与源文件

主角使用 Blender 4.5 LTS 制作，保留可编辑的网格、UV、骨架、权重和动作。以 glTF 2.0 或 GLB 交付运行资源；贴图与粒子素材可使用 Krita 等工具绘制。Blockbench 用于方块风格道具和场景附件。

首轮预算暂定主角 15000 三角面以内、64 根变形骨骼以内、每顶点最多 4 个骨骼影响、一张 1024 像素基础贴图及对应发光遮罩。预算是制作起点，依据实际渲染库约束和性能结果调整。保留材质分层与角色明暗，避免整只角色发白丢失形体。

参考板至少包含正侧背比例、跑步、蹬墙、腾空、冲刺和落地动态。主角外观以统一参考板为准。角色制作可自行完成或复用许可明确的模型；所有来源、许可和改动进入资产清单。仅有概念图或 AI 生成图片不算完成模型资产。

### 9.2 骨架和导出规则

骨架包含根节点、骨盆、脊柱、头部、四肢、耳朵与尾巴骨骼链，挂点覆盖手掌、脚底、身体中心和武器发射位置。眨眼和简易表情在基础动作之后加入。

Blender 的控制骨骼和约束服务于制作；导出时将动作烘焙到运行骨骼，统一轴向、单位、根节点和命名。灰模先通过深蹲、弯腰、甩尾三个变形测试，并验证一段循环和两段动作间过渡。

游戏位移由运动逻辑控制，首版主要使用原地动作。导出动画不能再额外推动玩家位置。脚部贴地、转向倾斜和耳尾惯性作为运行时修饰，限制最大偏转并在瞬移或加载时重置。

### 9.3 动作资产清单

| 分组 | 必需片段 |
| --- | --- |
| 形态 | 变身、解除、待机、警觉、死亡 |
| 地面 | 起跑、慢跑、快跑、急停、左右转向、潜行 |
| 空中 | 起跳、上升、顶点、下落、二段跳、轻落地、重落地 |
| 墙面 | 附着、滑墙、左右蹬墙 |
| 能力 | 冲刺起势和收势、Bash 瞄准和弹射、滑翔展开循环收起、牵引、下砸 |
| 战斗 | 三段刀击、弓蓄力保持释放、受击和恢复 |
| 生存适配 | 持物、使用物品、游泳、攀梯、乘坐和睡眠所需姿态 |

首轮技术小样只制作验证所需片段，正式交付覆盖全表。允许通过镜像、方向参数和连续速度混合复用片段；每项最终行为必须实际存在。

动画工程保存接触标记、脚步事件、视觉效果事件和可取消区间。战斗判定采用可测试的逻辑时间线，和视觉动画共享动作 ID 及时间约定。

## 10 画面 特效 声音和镜头

### 10.1 画风

使用 Iris 与配套 Sodium 作为光影运行基础，优先从 Mellow 修改。目标是彩色暗部、清楚的主角轮廓、柔和发光和远近层次；方块表面仍可辨识，洞穴和夜晚保持可玩性。

第一组视觉参考场景包括森林白天、森林夜晚、洞穴、水面、雨天，以及下界和末地可读性检查。颜色由场景配色、雾、光照和曝光共同决定。画面不能依赖截图专用曝光或固定镜头才成立。

提供流畅、均衡、精致三档及关闭光影选项。均衡为默认，运动模糊和强景深默认关闭，镜头震动较轻。首次安装可启用自带画风；已有自选光影时保留其选择并提示可切换。只承诺随项目验收的光影包。

### 10.2 技能和环境效果

Photon 用于粒子、拖尾、光束和效果编排。运行资源包含效果定义、贴图、材质及对应编辑工程。角色发光遮罩、光影 Bloom 和局部照明分别管理，防止重复 Bloom 造成过曝。

| 效果 | 表现与绑定 |
| --- | --- |
| 变身 | 身体轮廓聚光和短时散开粒子，随变身进度收尾 |
| 冲刺 | 从身体挂点生成方向明确的拖尾与少量残影 |
| Bash | 候选高亮、瞄准方向、聚光、释放冲击与尾迹 |
| 滑翔 | 展开和收起反馈，气流粒子不遮挡落点 |
| 牵引 | 锚点提示、方向反馈和到达粒子 |
| 下砸 | 下落尾迹、接地冲击环和短时尘光 |
| 灵光刃 | 刀光跟随武器挂点，命中效果位于实际命中位置 |
| 灵光弓 | 蓄力强弱、弹体、命中；取消时无残留 |
| 环境 | 灵迹附近的稀疏漂浮微粒、植被发光和水边氛围 |

动态照明先限制为角色和关键技能的少量光源，并设距离、数量及生命周期上限。它与 Iris 的兼容是技术验证项。关闭高级光照时仍显示基础自发光、方向和命中提示。

所有持续效果绑定明确的动作实例。取消、死亡、换维度、加载、区块卸载和资源重载均能清理；效果不能无限堆积。

### 10.3 音效和镜头

配套声音覆盖脚步、蹬墙、冲刺、Bash、滑翔、下砸、挥击、蓄力、命中、受击、变身与灵迹提示。环境声以短循环和稀疏事件组织。保留声音编辑源文件与游戏用 OGG，完成音量平衡和声音分类。

第三人称镜头采用可调距离、速度相关跟随和墙体避让；保留稳定准星。高速移动时镜头要跟得上，停止后不能持续漂移。小空间自动拉近。首版不强制战斗锁定镜头，Bash 期间仍允许瞄准。

外部渲染库通过项目内适配层接入。主角资产和动作 ID 不直接绑定某个库的内部类，降低替换成本。

### 11.3 技术验证失败的处理

| 问题 | 处理顺序 | 保持的目标 |
| --- | --- | --- |
| GemRender 无法稳定接入 | 缩小到单蒙皮模型定位问题；评估可用修复或另一个许可明确的 glTF 运行库 | 圆润变形主角 |
| Iris 与角色或 Photon 冲突 | 固定版本复现，明确唯一的合成和发光路径，再处理适配 | 正式版画风和关键技能可读性 |
| Mellow 无法形成目标画风 | 保留测试场景和参考板，替换可修改的光影基础或限定修改范围 | 方块轮廓与绘画感 |
| 动态光源过重 | 减少同时发光数量和作用距离，分档控制 | 角色轮廓、技能方向和命中反馈 |
| 动画质量不足 | 在灰模阶段调整绑定、动作和过渡；重新录制连续路线 | 动态连贯和操作响应 |

有限修复无法满足目标时，应提交已经跑过的样例、失败原因和替代方案。不得悄悄把圆润角色改为方块角色、移除内置画风，或把未完成项从验收表删除。

## 12 实施阶段与交付顺序

每个阶段必须先完成入口条件，再实现内容，最后按对应验收编号检查。失败项修复后复测；通过项只有在相关实现改变时才重复扩大检查。

| 阶段 | 工作 | 交付物 | 放行条件 |
| --- | --- | --- | --- |
| P0 计划冻结 | 审阅范围、默认值、验收、资产清单 | 确认版计划和决策记录 | 当前三项用户选择准确；首版范围已接受 |
| P1 可行性小样 | 工程、依赖、圆润灰模、光影、一个技能效果 | 可启动开发实例、依赖锁、短实机视频 | 蒙皮、过渡、阴影、特效与光影一起工作；记录性能基线 |
| P2 连续移动 | 变身、第三人称镜头、基础生存、全部移动能力灰盒 | 可循环跑酷测试路线 | 连续动作、墙角、碰撞、取消与恢复通过 |
| P3 正式主角 | 精修模型、正式动画、挂点、第一人称与生存适配 | 可编辑角色资产和完整动作表 | 比例、变形、持物、动态衔接达到参考标准 |
| P4 生存闭环 | 核心配方、成长、武器、碎片、死亡与存档 | 无命令可玩的完整成长流程 | 新世界进入玩法并完成解锁，重进后保留进度 |
| P5 世界内容 | 三类结构、定位、挑战和奖励 | 正式模板与自然生成证据 | 可发现、可进入、可退出、可重复，奖励正确 |
| P6 视听整合 | 光影风格、正式特效、音效、HUD和引导 | 默认画面方案与质量设置 | 日夜、天气、维度与快速运动下可读，无效果泄漏 |
| P7 发行验收 | 回归、性能、长时间运行、打包与文档 | 安装包、源码、源资产、验收报告 | 所有首版必需项通过，已知限制明确 |

P2 会实现全部移动能力的灰盒行为，P3 和 P6 再提高素材质量。声音、镜头与取消反馈从原型开始接入占位资源，正式交付前全部替换。任何阶段的小样都不能被称为正式首版完成。

## 13 完成标准和证据

详细验收步骤在 [验收计划](ACCEPTANCE.md)。覆盖功能、模型和动画、画面特效、原版交互、世界内容、持久化、性能及安装恢复。

每条验收标记为未测、通过、失败或受阻，记录构建版本、环境、步骤、预期和证据位置。构建、自动测试、编辑器预览、实机画面是不同证据，不能互相替代。

代理负责按参考板和动态片段执行技术与视觉验收，修复已知偏差。视觉自检需覆盖正侧背、近景、运动、暗处与发光背景。仅展示最佳角度截图不足以通过。用户无需逐项代为操作验收；用户提出的审美偏差进入问题记录。

首版正式交付要求所有必需项通过，无数据损坏、崩溃、无法操作、进度卡死或可重复的关键视觉错误。当前没有任何已通过的游戏验收项。

## 14 后续自主执行方式

计划已确认，当前进入 P1 工程准备。后续按 P1 至 P7 推进，代理承担代码、可制作的模型与动画、特效、测试、修复和交付。

阶段性更新报告已完成内容、实际证据、失败项和下一步；无需让用户反复确认普通实现细节。无法获得测试条件时写明受阻项目，保留其状态并继续其他独立工作，不能填写通过。

开发按阶段保留可回退检查点，资产源文件与游戏导出文件分开保存。之后新增或修改的用户文件先检查再编辑。安装包从锁定的依赖构建，默认开发世界和正式存档隔离。

新增付费服务、购买素材、对外发布、上传私有内容或删除用户既有资料不属于这份计划的自动执行范围。常规本地开发、公开依赖下载、生成测试世界和验证步骤属于实现范围。
